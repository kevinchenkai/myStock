## 0. 一句话

两份方案方向一致：**覆盖率与成交是相反目标、先立朴素波动率基线、策略改为多日库存式、Web 串起「明日建议 → 复盘 → 真实挂单对照」、不做 RL/TFT/HMM、Web 只读不下单。**
差异在侧重：Claude 提供了量化证据（模型 ≈ 朴素基线、触价经济性），Codex 提供了工程可信度（版本化、只读保证、交易日历、事件账本）。合并原则：**先修可用性硬伤 → 再立评估地基 → 再做预测层实验 → 最后策略 v2 与页面**；Codex §8 的大规模建表与 §14 外部特征暂缓，等预测层拿出增量证据再立项。

### 1.3 v0.2 新发现：预测生成时点未受控，且 REPLACE 抹掉了证据（P0，双方方案均未覆盖）

Codex v1.3 对「02:40 PDT 批次」提出质疑，核查结果比质疑更严重：

- 本机**没有任何 cron / launchd 条目**在跑 `ml.sh`（crontab 仅一条已注释的无关任务）。`ml_sync_log` 里 `predictions` 的写入时刻是手工触发的，分布在 01:16 / 01:33 / 02:05 / 02:40 / 03:50 / 07:19 / 08:06 / 08:29 / 16:33 / 16:50 / 17:48 / 18:23 / 18:51 / 19:42（PDT）。
- `fetch_daily` 按 `period` 增量抓取，yfinance 在交易时段内会返回**当日未收盘的 in-progress bar**；`_ohlc_ok` 与 `predict_next_day` 都没有「最后一行是否已收盘」的判断，最后一行是什么就拿什么当 T 收盘。
- 已发布的报告中至少三份用了盘中价当「收盘」做次日预测：

| 报告目录 | 生成时刻（PDT → 市场当地） | 报告写的「截至 X 收盘」 | 真实收盘 |
| --- | --- | --- | --- |
| 2026-08-17 | 19:42 → HK 08-18 10:42（开盘中） | HK.00700 截至 08-18 收盘 439.00 | 442.40 |
| 2026-08-27 | 07:19 → US 10:19 ET（开盘中） | US.NVDA 226.00 / TSLA 351.87 / PDD 85.21 | 227.98 / 354.81 / 84.69 |
| 2026-09-01 | 18:51 → HK 09-02 09:51（开盘 21 分钟） | HK.00700 截至 09-02 收盘 435.20 | 438.20 |

- 这些错误版本在 `ml_predictions` 里**已查不到**：同日稍后的正常运行以 `(code, as_of)` 主键 `INSERT OR REPLACE` 覆盖了它们。这正是 Codex F02「版本不可覆盖」要防的事，也是 v0.1「加四列即可版本化」不成立的实证。
- 同一份报告里 US 与 HK 的 as_of 可以不同（08-17 报告：US 截至 08-17、HK 截至 08-18），读者无从分辨哪一半是盘中值。

**结论**：v0.1 §2「满足收盘后预测、开盘前挂单的时序」的说法撤回。第一批必须加入「收盘守卫 + 调度」两项（见 §2），第二批的版本表必须做到已发布行不可覆盖（采纳 Codex §8.1）。

## 2. 合并后的分批顺序

> 每批可独立审查、独立交付；后一批不依赖前一批的实验结论，只依赖其代码。工期为单人粗估，不含前向 shadow 等待。

### 第一批：可用性硬伤修复（约 3 天，以 Codex 阶段 A 为主）

| 项 | 范围 | 验收 |
| --- | --- | --- |
| 只读保证 | Web 与纯查询路径（`strategy` / `review` / `data`）使用 `mode=ro` 连接，`db.py` 增 `get_ml_connection_readonly()`；`backfill` / `report` 保留离线写入口，但读行情透传 `db_path`（采纳 Codex v1.3 的边界限定） | 在 Web 路径上执行写 SQL 必失败（加测试）；离线回填可向指定测试库写入 |
| 收盘守卫 | 采集与预测都按市场日历判断「最新一行是否已收盘」（IANA 时区 America/New_York / Asia/Hong_Kong 判 session 结束）；未收盘的 in-progress bar 不入库、不作 as_of；报告与留档记 `decision_at / published_at` | 盘中触发 `ml.sh train` 不会产生以盘中价为「收盘」的预测（时钟可注入的单测） |
| 触发方式（用户已定） | **近期保持人工手动触发 `update.sh` / `ml.sh`，先迭代效果并同步文档，自动调度以后再议。** 因此收盘守卫要对「任意时刻手工运行」兜底：`ml.sh` 起步时打印两个市场的 session 状态；某市场仍在盘中则该市场的预测**跳过并明确提示**（不生成、不覆盖上次留档），另一市场照常。`ml.sh` 注释与 README 删除「cron 每工作日」的表述，改写为手动流程 | 盘中手工运行只产出已收盘市场的预测，日志能看出跳过原因；`ml_sync_log` 记 `skipped_in_session` |
| 交易日历窗口 | `days` 按标的自身交易日取最近 N 个 session；缺预测 / 缺 1h / 缺日线的日子保留为状态行（`missing_prediction / missing_bars / missing_daily`） | 缺一天页面显示一天缺口，不再静默截窗 |
| 参数校验 | 无效代码返回 400 并列出原因；重复代码去重保序；不再静默回退默认股票 | 加 API 契约测试 |
| 交易单位 | 在现有富途快照采集（`futu_client.get_market_snapshot`，已取 turnover_rate / amplitude / 52 周）里加 `lot_size` 一列进 `stock_profiles`；ML 侧 `LOT_BY_CODE` 从它读取，缺失时回退并标注近似；策略「每次买多少股」与「每手」分开配置 | 01810 手数来自快照而非推断；策略 qty 可配 |
| 采集质量 | `_ohlc_ok` 拒绝 inf 与 high<low；`recompute_gaps` 透传 `db_path` | 加单测 |

### 第二批：最小留档与评估地基（约 4–5 天，= Codex v1.3 第二批）

| 项 | 范围 | 验收 |
| --- | --- | --- |

| skill 指标 | `walk_forward_eval` 输出 `pinball_skill_low/high = 1 − model/naive`、raw 与校准后分开评分、滚动覆盖偏差 | 报告总览增 skill / 覆盖偏差列 |

### 第三批：预测层实验（约 1.5 周，Codex E1→E5 顺序 + Claude A1/A2 候选）

每轮只改一个机制；共同样本掩码、相同测试日期、相同基线。

| 序 | 实验 | 候选内容 |
| --- | --- | --- |
| E1 | 训练窗与校准窗 | 全历史 vs 最近 504/756 session；校准集 25% 尾部 vs 固定 60/120 session |
| E2 | 目标标准化 | 原生 y vs `y / vol_20d`（或 ATR）标准化后还原 |
| E3 | 正则化 | `num_leaves 15→7`、`min_child_samples 30→50`、显式 bagging、时间序早停 |
| E5 | 波动率特征 | 日线组：Parkinson / Garman-Klass / Rogers-Satchell、vol_5/vol_20、vol-of-vol；1h 组：已完成 bar 收益平方和的 1/5/22 session 聚合、尾盘收益 |
| E4 | 自适应校准 | 固定 q vs 最近 60 session OOF 残差滚动 q；其后才试 ACI；分侧 q 须先定误覆盖预算（`α_low + α_high = 0.30`） |
| E6 | 多分位与池化 | 多 α 网格 + 单调重排；6 支池化（标签标准化 + `market` / `stock_id`）vs 独立模型 |
| E7/E8（可选） | 跳空分解、触价概率 | E7 先做误差归因，联合残差再校准；E8 触价概率用 Brier / 可靠性图验收，触价后收益先诊断后建模 |
