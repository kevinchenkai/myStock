## 3. 两个 P0 的功能与验收

### WEB-01：数据时间与采集状态（先做）

**触发场景**：用户打开首页或单股详情时，不应把几天前的缓存理解为最新行情，也不应因为长周末把正常日线误报为采集失败。

1. 在首页增加可折叠的“数据状态”，在个股详情显示该股行情／资料／快照的来源与时间。复用 `sync_log`、已有行级时间和行情日期，不建设独立监控系统。
2. 区分 `data_as_of`（来源业务时间／交易日）、`last_success_at`（成功采集）与 `last_attempt_at`／结果；前端不能把一个“最近同步”套到所有数据源、市场或股票。没有历史证据的字段返回 null。
3. 对本次快照采集保存结构化结果：至少区分 ok、partial、empty、error、unsupported／unknown；是否拆出小表由 Astra 决定，禁止靠解析面向人的错误文案生成永久数据契约。旧来源只能显示已有 source 级状态时，明确为汇总，不伪造逐股成功。
4. 日期判断用交易所时区；日线是否缺少已收盘交易日复用已存在的日历事实及收盘确认规则。未知市场、日历越界或输入时间不确定时显示“无法判断”，不能回退为最新。若需要抽公共 helper，保持改动局部，不改变 ML 的既有决策／校准时间。
5. 采集失败保留原有效数据并标注旧缓存；明确失败或空结果不显示成功绿点。页面给简短说明，技术错误放折叠详情并脱敏，不能露出账户号、凭据或私有路径。

**验收**：固定时钟测试 HK/US、US 夏令时、周末／节假日／跨日、盘中未收盘、日历越界；测试“本次失败但有旧值”“最新整体 ok 但个股缺失”“来源时间未知”。浏览器时区变化不改变同一交易日的业务判断。

### WEB-02：单股缓存快照卡

**触发场景**：用户打开单股详情，能看到采集时的价格、日内范围、停牌状态和每手股数，不用在资料表里猜数据含义。

1. 扩展既有 `fetch_snapshots`／`snapshot_fields`，复用同次响应：`update_time`、`last_price`、`prev_close_price`、`open_price`、`high_price`、`low_price`、`volume_ratio`、`suspension`、`sec_status`，继续取已有 lot_size 与 price_spread。有限字段集，不全量存原始 SDK 响应。
2. 优先 additive schema 扩展，保留 `snap_synced_at` 与 yfinance `synced_at` 独立；保存来源行情时间原文、时区和标准化时间。字段解析兼容当前 SDK 的缺列、NaN、枚举字符串与未知状态。部分标的缺失不能算全部成功；超过 400 标的时分批并按官方限制节流，不无限并发。
3. 卡片标“Futu 缓存快照”，展示来源行情时间、采集时间、最新价、由 last/prev_close 算出的涨跌、日内高低、量比、每手股数与停牌状态。缺值显示“—／未知”，未知停牌不能显示正常。HKD／USD 分别标注；本轮不需要盘前盘后专页。
4. `price_spread` 若展示，标“当前向上报价档位间隔”，放说明区；**不称买卖价差，不自动填入回溯 tick，不当作跨价区的证券规则**。本轮不新增 bid/ask 深度、即时交易单位校验或自动挂价。
5. `rules_effective_from` 旧字段不用于说明规则正式生效时间；这里只展示本次观测时间。不回填历史规则，也不因显示 lot_size 就关闭遗留 P2-3。

**验收**：合成 HK／US 快照、缺列、0/None/NaN、停牌、prev_close 无效、部分成功与过期缓存。重复采集幂等；Futu 写入不覆盖 yfinance 资料，反之亦然；HTTP GET 在断网／禁用采集调用时仍可显示缓存。
