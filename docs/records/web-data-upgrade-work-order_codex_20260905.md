用户暂缓成本较高的 ML 模型升级，改为优化日常看盘的 Web。目标是让用户明确知道**数据截至何时、个股当前快照怎样、近期有哪些公司事件**。

- 使用 `codex/web-data-20260905` 分支及自己的隔离工作树；若同名分支已有工作，先检查，不强制重置。保留本地已有改动，不与其他任务同时改同一文件。
- 执行方完成实现、验收、文档和 Git 推送。可启动绑定本机的独立预览服务，使用隔离数据库；演练迁移前备份隔离输入并验证恢复。
- **本工单没有新增修改原运行库、重启 8888、合并部署、公网报告发布、自动调度或真实交易的授权。**此前 ML 轮次的具体部署授权不扩大成此次新功能部署。先交付可审查的代码、预览与迁移／回退步骤，不为常规实现重复确认；若当前用户已另给本轮部署授权，按授权执行并如实记录。

## 2. 三批候选设计（未批准）

### WEB-01：数据时间与采集状态（先做）

**触发场景**：用户打开首页或单股详情时，不应把几天前的缓存理解为最新行情，也不应因为长周末把正常日线误报为采集失败。

1. 在首页增加可折叠的“数据状态”，在个股详情显示该股行情／资料／快照的来源与时间。复用 `sync_log`、已有行级时间和行情日期，不建设独立监控系统。
2. 区分 `data_as_of`（来源业务时间／交易日）、`last_success_at`（成功采集）与 `last_attempt_at`／结果；前端不能把一个“最近同步”套到所有数据源、市场或股票。没有历史证据的字段返回 null。
3. 对本次快照、未来事件采集保存结构化结果：至少区分 ok、partial、empty、error、unsupported／unknown；是否拆出小表由 Astra 决定，禁止靠解析面向人的错误文案生成永久数据契约。旧来源只能显示已有 source 级状态时，明确为汇总，不伪造逐股成功。
4. 日期判断用交易所时区；日线是否缺少已收盘交易日复用已存在的日历事实及收盘确认规则。未知市场、日历越界或输入时间不确定时显示“无法判断”，不能回退为最新。若需要抽公共 helper，保持改动局部，不改变 ML 的既有决策／校准时间。
5. 采集失败保留原有效数据并标注旧缓存；明确失败或空结果不显示成功绿点。页面给简短说明，技术错误放折叠详情并脱敏，不能露出账户号、凭据或私有路径。

**验收**：固定时钟测试 HK/US、US 夏令时、周末／节假日／跨日、盘中未收盘、日历越界；测试“本次失败但有旧值”“最新整体 ok 但个股缺失”“来源时间未知”。浏览器时区变化不改变同一交易日的业务判断。

### WEB-02：单股缓存快照卡

**触发场景**：用户打开单股详情，能看到采集时的价格、日内范围、停牌状态和每手股数，不用在资料表里猜数据含义。

1. 扩展既有 `fetch_snapshots`／`snapshot_fields`，复用同次响应：`update_time`、`last_price`、`prev_close_price`、`open_price`、`high_price`、`low_price`、`volume_ratio`、`suspension`、`sec_status`，继续取已有 lot_size 与 price_spread。有限字段集，不全量存原始 SDK 响应。
2. 优先 additive schema 扩展，保留 `snap_synced_at` 与 yfinance `synced_at` 独立；保存来源行情时间原文、时区和标准化时间。字段解析兼容当前 SDK 的缺列、NaN、枚举字符串与未知状态。部分标的缺失不能算全部成功；超过 400 标的时分批并按官方限制节流，不无限并发。
3. 卡片标“Futu 缓存快照”，展示来源行情时间、采集时间、最新价、由 last/prev_close 算出的涨跌、日内高低、量比、每手股数与停牌状态。缺值显示“—／未知”，未知停牌不能显示正常。HKD／USD 分别标注；本轮不需要盘前盘后专页。
4. `price_spread` 若展示，标“当前向上报价档位间隔”，放说明区；**不称买卖价差，不自动填入回溯 tick，不当作跨价区的证券规则**。本轮不新增 bid/ask 深度、即时交易单位校验或自动挂价。
5. `rules_effective_from` 旧字段不用于说明规则正式生效时间；这里只展示本次观测时间。不回填历史规则，也不因显示 lot_size 就关闭遗留 P2-3。

**验收**：合成 HK／US 快照、缺列、0/None/NaN、停牌、prev_close 无效、部分成功与过期缓存。重复采集幂等；Futu 写入不覆盖 yfinance 资料，反之亦然；HTTP GET 在断网／禁用采集调用时仍可显示缓存。

### WEB-03：公司事件卡与历史标记

**触发场景**：用户看单股 K 线时能解释分红／拆股相关跳变，并看到供应商提供的近期财报或除息安排。

1. **先复用已有数据**：从 `daily_quotes.dividends/stock_splits` 展示历史事件列表并在现有 K 线上做轻量标记。只处理有限正值／有效拆合股比例，注明来源、每股金额与比例方向；事件日期不是到账日期，不改变当前 P&L、价格复权或账户资金。
2. **新增低频事件采集**：使用当前 yfinance 的 `get_earnings_dates(limit=12)` 与 `calendar`，新增独立 collector／纯解析函数。在既有人工更新管线中加入可独立失败的阶段。只处理当前持仓与已有 ML 关注股去重后的 HK/US 集合，不全市场扫描。
3. 同一交易所自然日已成功或明确 empty 的标的不重复请求；网络／限频错误采用有限退避与重试冷却，必须有超时或总耗时约束，不能反复撞接口。无远端数据时保留其他功能，不能阻断账户、日线和快照更新。
4. 缓存字段至少覆盖：code、event_type、事件日期或日期范围、可选事件时刻与来源时区、date_precision、预计／已报告／未知状态、source、fetched_at、可选除息金额／币种。`first_seen_at` 只能表示本系统首次观察，不能冒充官方发布时间。不持久化不必要的原始响应。
5. 未获得权威确认的未来日期标“预计”；只有日期时不转换成某个 UTC 午夜。保留区间，不擅自取区间首日；未知时区保留不确定状态。过去日期仅凭时间已过不能升级成“已发布”。
6. 不同接口返回同一事件要去重，日期修订要替换当前显示并保留最小修订线索，不能累积成两场财报。失败不清除旧缓存；新成功响应不再包含某未来事件时，标“待确认／来源已变更”，不能永远挂在近期列表。财报／除息／派息日分开，不能把类型合并去重。
7. 单股详情新增“公司事件”小卡：未来 30 自然日安排与最近一年历史事件，可折叠。财报接口 empty／error 时显示“暂无可用日程／获取失败，保留上次记录”，不能显示“未来没有财报”。列表为必要交付；图表只标有明确历史日期的事件，日期范围不伪装成确定点。

**验收**：mock 覆盖 dict／DataFrame／None、HK 缺数据、日期范围、日期修订、重复来源、429／超时、同日重跑、未来转历史、股息币种未知、拆股与合股。用合成事件证明接口缺数据时日线／其他个股正常。不得拿已有未来日期倒填历史 ML 特征。

## 3. 实现位置与兼容要求

主要范围：`mystock/collectors/futu_client.py`、`mystock/collectors/yf_client.py` 或同层新事件模块、`mystock/db.py`、`mystock/schema.sql`、`mystock/pipelines/init_load.py`／`update_load.py`、`mystock/web/app.py`／模板／静态 JS/CSS、相关 tests 与现行 docs。

建议新增只读 `/api/data-status`、`/api/stock/<code>/snapshot`、`/api/stock/<code>/events`，具体命名可按现有风格局部调整，并记录返回字段。SQL 参数绑定、有限查询窗口、确定排序、null 与 0 区分；新增字段为 additive，原 API 不改语义。

旧库缺新增表／列时，新卡片显示需要更新／不可用，原页面继续工作；Web 禁止趁 GET 迁移。CLI 迁移须可重复执行，备份使用 SQLite 一致性备份方式，不能在活动库上只拷主文件漏掉 WAL。在隔离副本验证迁移与恢复，不改运行库来完成测试。

当 API 文档与当前 SDK 不符时，用兼容解析、unsupported 状态或缩减到有效字段；不能静默 pip 升级全环境。可对明确公开的测试标的做有界行情／事件只读探测，结果写 ignored 目录，不查询账户明细来凑测试。
